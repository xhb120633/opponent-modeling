# Data, execution and claim boundaries

The package includes plotted point estimates, published vector figures, Figure 2A paper-visible match scores, four complete audited 20-match hider-versus-ToM2 round records, GPT-5.4 Figure 2C seeker/hider round records, and selected row-level development outputs for Figures 3 and 4. It does not include the complete observation-level data for all historical studies. Some archived model outputs contain personal infrastructure paths or account-specific metadata; sealed-final material remains excluded. Missing or invalid cells must not be replaced by zero or scored from partial checkpoints.

The main figures combine historically distinct studies. A figure-builder script may require internal audit JSONs and source files not shipped in this code artifact; its presence documents the plotting logic but **does not** imply that `python build_figures.py` will reproduce the PDF from this ZIP alone. Full experimental reruns additionally need model revisions/weights, GPU capacity, external simulator dependencies, and for GPT experiments API access. Some old checkpoint revision hashes, original runtime libraries and full project-wide compute accounting were not recoverable. These limitations are part of the paper's provenance, not repaired by repackaging.

The supplied CSVs are for inspecting reported values and figure labels. `reanalyse_live_raw.py` recalculates Figure 2A means from match scores and Figure 2B/2C payoffs and accuracy from released round-level records; `reproduce_audited_cells.py` recomputes the Figure 2B bootstrap intervals from match scores. `reanalyse_selected_raw.py` recalculates Figure 3a/b/d/e/f and Figure 4d/e point estimates from released row-level records. None independently verifies original simulator targets or every model reply. Portable source substitutions replace machine- and account-specific defaults; the Figure 2C records also replace one account-specific deployment identifier, with original/released hashes and counts in the manifest. Hash-bound historical preflight checks may require original frozen files and will not automatically pass with a rehomed copy. Anyone rerunning a study should first rebuild a new prospective configuration and record its own model, source, data and environment hashes. Do not silently label such a new run as byte-identical to the archived one.

No credentials are included. API adapters read user-provided environment variables; do not commit `.env` files. `TOM_AZURE_ENV_FILE` is optional and `TOM_AZURE_DEPLOYMENT` identifies a deployment supplied by the user. The R3/R4/R5 scripts need `TOM_R3_RUN_DIR` when executed; the historical matched G03 and T04 entrypoints also need `TOM_PACE_ROOT` pointed to a compatible archived project layout. The public release contains no Git metadata, author names, repository URL or personal filesystem location.

Historical experiment tests require excluded training splits or a compatible PyTorch runtime. The self-contained `verify_artifact.py` checks file integrity and Python syntax only; `reproduce_audited_cells.py` checks the four released score vectors. Neither substitutes for rerunning the models.
